# v2026.10.24

> 🎉 1024 程序员节快乐！

自 v2026.10.23 以来的收口：桌面端中英双语与主窗口控件化落地，注册工作流的阶段体全部拆出
`handlers.py`；英文界面残留的中文提示、语言切换卡死与注册失败分类的潜在漂移一并修掉。

## 新增功能

- **中英双语界面（切换无需重启）** —— 新增 `Loc` / `StringsEn` / `{loc:Tr}` 本地化引擎，设置页可选
  「跟随系统 / 简体中文 / English」，切换即时生效；首次启动跟随系统 UI 语言，选择随配置落盘。
- **主窗口控件化** —— `MainWindow.xaml` 由 874 行降到 54 行，标题栏、侧栏、筛选/分页条、
  账号表（含右键菜单）与任务/日志控制台拆成 5 个独立控件；控件以依赖属性与方法暴露状态，
  窗口不再按名访问内部元素。界面行为不变。
- **注册阶段模块化** —— 注册工作流 `handlers.py` 从 1175 行降到 506 行，bootstrap / identity /
  auth / register 四组阶段体各自成模块，工作流只保留阶段顺序与转发；`patch.object` 与历史
  导入路径全部保持有效。

## 修复问题

- **英文界面里仍显示中文** —— EN 模式下 25 处提示（「请先选择一个账号」「任务进行中」
  「环境自检」「导入完成：成功 N 条」、账号测活对话框，以及批量进度窗的「取消任务 / 正在取消」）
  以及手写在 `Models/` 里的批量进度对话框都未走翻译表；现全部本地化，并新增门禁：把字面中文
  直接写进 `MessageBox.Show`、`Notify*`、`DialogFactory.Show*Async` 或 `Content`/`Text`/`Title`
  属性即失败。
- **切换语言后界面卡死** —— 翻译绑定刷新跨 Dispatcher 使用同步 `Invoke`，UI 线程等待时会自锁；
  改为 `BeginInvoke`。
- **单账号协议支付残留明文 Access Token** —— 已移除不可达的单账号协议支付窗口链；启动与退出时
  会清理历史遗留的明文 Access Token 临时文件。
- **瞬时锁冲突让整批注册失败** —— 跨进程阶段门在锁被短暂占用时直接判失败；现在先重试再判定。
- **OTP 校验重试丢弃逐请求认证头** —— 重试沿用了首次请求的头集合；现在保留每个请求各自的
  `x-access-flow-invocation-id` 等头（与 HAR 一致）。
- **内部错误被误判为网络故障** —— 「哪些异常类型算代码缺陷」原本在三个模块各存一份副本，
  靠注释互相提醒同步；统一为 `kernel.error_classification.INTERNAL_EXCEPTION_TYPES` 单一 owner，
  并加守卫测试禁止再次内联。
- **注册选项对话框绕过统一对话框工厂** —— 两个注册选项窗口各自手搓窗口外壳、表单行与按钮行；
  改走 `DialogFactory` 的表单/动作行 seam，`MainWindow.Register.cs` 由 749 行降到 668 行。
