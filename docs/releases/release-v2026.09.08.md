# v2026.09.08

本版本完成无头浏览器注册链路的日志、调度和桌面协议加固，并包含此前工作区中
尚未发布的注册架构整理。重点是让一次注册从桌面命令、浏览器运行、进度账本到
账号测活都能可靠关联、恢复和审计。

## 桌面注册结果契约

- WPF 的全部注册命令统一传递 `--desktop-ipc`，不再出现进程成功退出但桌面端
  收不到结果 payload 的情况。
- 普通批量注册、目标 AT=200 模式和 CLI 前置失败统一返回 `ok`、`total`、
  `success`、`failed`、`batch_id`；前置失败附带脱敏后的 `error` 和
  `exit_code`。
- 桌面端继续通过唯一终止信封消费结果，避免从普通控制台文本推断成功与失败。

## 注册遥测与计时

- `run_id` 在首条 `started` 事件前绑定，首尾事件和文件日志可完整关联。
- 阶段耗时归属已修正为“离开阶段时结算当前阶段”，不再把等待时间记到刚进入的
  下一阶段。
- 成功流程只产生一次 `completed` 终止事件，不再重复上报成功。
- JSON 日志补充注册批次、驱动、尝试次数、失败分类和可重试性等结构化字段。

## 浏览器调度与账号测活

- 浏览器注册先取得认证阶段 admission，再创建浏览器进程或上下文，减少并发批次
  中空闲浏览器占用内存和句柄。
- 显式同步推广检查开启时，不再为相同账号重复排队执行推广检查。
- 账号测活队列增加 lease、heartbeat、过期回收和中断 worker 恢复；退出进程
  遗留的 `running` 任务可重新领取，不再永久卡住。
- 注册结果附带测活调度摘要，便于桌面端区分同步检查、已排队和跳过状态。

## 日志安全与运行数据

- 进度账本和 IPC 使用稳定哈希账号引用；操作者界面只显示遮罩邮箱。
- 持久日志会脱敏邮箱和敏感值，注册热路径的直接 `print()` 已迁移到安全输出。
- `runtime/registration_progress.jsonl` 支持按大小轮转，并通过跨进程写锁避免
  并发写入和轮转互相破坏；质量指标读取当前文件及轮转备份。
- delayed-import 数量从基线 402 降至 396，没有通过放宽架构基线规避检查。
