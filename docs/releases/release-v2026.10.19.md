# v2026.10.19

自 v2026.10.15 以来的运行形态硬化：安装包开始内置固定 CPython，桌面端与 CLI 的启动/刷新成本继续下降，
注册编码风格（阶段函数的 `workflow` 参数）与类型门禁同步收口。

## 新增功能

- **安装包内置 Python 运行时** —— 发布包自带固定版本的 CPython 3.12.15（含依赖），Windows 上不再要求预先安装 Python
  或执行 `pip install`；首次启动即可运行 `--doctor`。显式配置的 `runtime.python_path` 仍然优先（例如开发用 venv），
  内置解释器只接管默认值。Node.js 仍为外部依赖。
- **桌面端账号列表增量刷新** —— 常驻读通道改为按 `updated_at` 游标返回变化行与全量 ID 集合；434 账号的空闲刷新
  从约 681 KB 降到约 3.5 KB，账号变动会触发全量兜底。
- **CLI 与 `--doctor` 提速** —— 命令模块改为懒加载，`python chatgpt_phone_reg.py --help` 与普通命令不再导入 HTTP/浏览器栈；
  `--doctor` 的依赖探针并发执行，未读配置键扫描按文件 mtime 指纹缓存（冷启动约 3.1 s，暖启动约 1.7 s）。
- **浏览器进程池内存上限** —— 新增 `registration.browser_process_pool.max_total_rss_mb`（默认关闭）。开启后汇总浏览器
  进程树的 RSS，超过上限时回收一个空闲槽位并在下次取用时重建；采样失败只会跳过本次判断。
- **可选 Sentinel 常驻 worker** —— `SMS_SENTINEL_WORKER=1` 时复用同一个 Node 进程连续发行 token，省去每账号 2–3 次
  Node 冷启动；它只替换传输，token 校验与 runner 判定不变，传输失败自动回退一次性运行。
- **完整 CLI 参考** —— 新增 `docs/current/cli-reference.md`，由真实 argparse 解析器生成（约 190 个选项），
  并纳入文档门禁，避免与代码漂移。

## 修复问题

- **长批次与常驻桌面内存持续增长** —— 出口地理、支付 egress 探针、会话文件状态与 auth dump 形状四处进程级缓存
  原本只在“同一个键再次查询”时过期，代理轮换或账号目录增长会让它们无界累积。现在分别有固定上界并在溢出时
  先清过期项，丢条目只意味着一次重测/重读。
- **桌面端每条后端命令占用最多约 8 MB 输出缓冲** —— 后端输出改为收到 IPC 信封即解析，只保留 256 K 字符的诊断尾部；
  畸形信封仍进入尾部供退出后的解析器报错。
- **`--doctor` 重复全量扫描配置** —— 未读配置键扫描改为按 `(path, mtime, size)` 指纹缓存，源码未变时不再重扫；
  缓存损坏或 schema 漂移会自动退回现算，告警内容不变。
- **支付 lane 静默吞异常与可预测的追踪 ID** —— 支付链路不再吞掉分类异常，失败会带阶段与失败类进入日志与结果；
  trace/proxy session 标识改用 `secrets` 生成，不再可预测。
- **注册 OTP 阶段对空配置取属性** —— 类型标注后暴露 `wait_email_otp` 在配置为 `None` 时会调用 `.get`；已按注册 lane
  既有写法收窄为 Mapping 判定，避免少见的启动路径崩溃。
